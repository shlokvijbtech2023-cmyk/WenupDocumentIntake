System Architecture

Engineering Design & Responsibility Boundaries

1. Explicit Responsibility Boundary

LLM Responsibility (NLU Only)
  • Extract structured field candidates from natural language
  • Interpret natural multi-field answers & corrections
  • Identify ambiguous phrasing & draft conversational clarification
Deterministic Application Logic (Guarantees)
  • Schema validation & allow-list enforcement (Pydantic)
  • Deterministic contradiction backstop across turns
  • Interview question progression & completion checking
  • Authoritative document templating (zero fact invention)

2. Canonical State vs Conversation History

The conversation history is never the source of truth for the document. State is explicitly modeled in IntakeState, ensuring corrections immediately overwrite stale data and incomplete fields remain clearly flagged.

3. Resilient LLM Abstraction & Automatic Fallback

All provider calls (OpenAI, Gemini) implement the unified LLMClient interface and are wrapped in FallbackLLMClient. If a provider experiences rate limits, network outages, or auth errors, the turn automatically completes on the deterministic mock without stalling the user.

4. Zero-Persistence Privacy Guarantee

Personal intake data is held purely in transient in-memory sessions with a 2-hour TTL. No database, cookies, or localStorage are used. Evaluators can reset the session at any time with the "Start Over" button.
